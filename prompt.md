# Product Brief: User-Post-Comments Web App

Act as our tech lead. Read this brief and produce a complete, step-by-step implementation plan for the product. You may adjust choices where the brief is silent, but do not change anything marked **(locked)** without saying so.

## Product

A simple community web app where people create accounts, write posts, and discuss them via comments. Comments support **nested replies** (reply to a reply), displayed as an indented threaded tree.

Core user journeys:

1. A visitor signs up, logs in, and logs out.
2. A logged-in user can publish a post (title + body), edit it, and delete it — only their own posts.
3. Anyone can view the post list (newest first, paginated) and read any post.
4. A logged-in user can comment on any post and reply to any comment (nested).
5. A user can delete their own comments (or entire post, which removes its comments).
6. Everything persists across server restarts.

## Scope (specific features)

- **Auth**: full register/login/logout (**(locked)** Laravel Breeze, Blade variant).
- **Posts**: create, read (list + detail), edit, delete — owner-only via authorization policy.
- **Slug**: URL-friendly unique slug per post, autogenerated from the title.
- **Comments**: top-level comments + **nested replies** via a self-referencing `parent_id`. Nesting depth capped (~3) to keep trees manageable. Parent must belong to the same post.
- **Thread rendering**: recursive Blade partial renders the indented comment tree with author name, avatar, relative time.
- **Validation**: post title 3–255, post body min 10 chars, comment body 1–2000.
- **UI**: Blade views styled with Tailwind CSS, flash messages for success/error.
- **Data**: PostgreSQL for both local dev and production.

## Constraints

- Runs **identically** in local Sail Docker and on Render — no dev/prod drift.
- Deployable on Render from a GitHub repo via a `render.yaml` blueprint.
- Production must survive service restarts (DB-backed sessions/cache/queue, `DATABASE_URL`).
- Beginner-friendly for CS students: minimal moving parts, documented commands, seed data.
- No third-party auth, no file uploads, no social features yet.
